## July 26, 2026

- <VPBadge type='info'>Hosted</VPBadge> **Minecraft 26.2 players can join the Minekube hub again.** They could not join between June 16 and July 26: the hub backend was still running a 26.1 protocol build while the edge accepted 26.2 connections. Server-list pings kept looking healthy throughout, because the Connect edge answers pings itself. Fixed and deployed on July 26. (Internal repository, no public link.)
- <VPBadge type='warning'>Self-hosted</VPBadge> **Gate v0.68.31 contains a security fix for PROXY-protocol handling.** If you expose Gate directly, upgrade to [v0.68.31](https://github.com/minekube/gate/releases/tag/v0.68.31).
- <VPBadge type='warning'>Self-hosted</VPBadge> **Three separate bugs that broke modded servers are fixed in [Gate v0.68.30](https://github.com/minekube/gate/releases/tag/v0.68.30):** large mod registry payloads over 1 MiB no longer kill the connection, Forge clients no longer lose their hostname when routed through a second proxy, and Gate Lite now warns you when it is ignoring `forwarding`, `onlineMode` or `servers` settings instead of silently accepting them.
- <VPBadge type='warning'>Self-hosted</VPBadge> **Gate's bundled GeyserLite is current again.** It was stuck at v0.3.17 from June 30 to July 26 while GeyserLite itself reached v0.4.9, so self-hosted Gate shipped a stale Bedrock runtime for that period. [Gate v0.68.30](https://github.com/minekube/gate/releases/tag/v0.68.30) ships GeyserLite v0.4.9.
- <VPBadge type='danger'>Still broken</VPBadge> **Managed GeyserLite for self-hosted Gate Lite still does not start.** It remains unable to complete its Minecraft data download, and no Bedrock listener comes up. It now fails immediately with an error telling you to point it at a prebuilt GeyserLite binary, instead of hanging your proxy startup for ten minutes with no explanation. The underlying startup failure is still open. (Internal repository, no public link.)
- <VPBadge type='info'>Hosted</VPBadge> **Bedrock players with a Microsoft/Xbox account but no linked Java account can now be admitted to a Connect endpoint.** This is off by default and enabled per endpoint by Minekube on request — there is no self-service control yet. Refused Bedrock joins now report a reason instead of timing out with a bare network error. (Internal repository, no public link.)
- <VPBadge type='info'>Hosted</VPBadge> **Connect endpoint status pings could stop resolving on a proxy machine after a network interruption** and stay broken until that machine restarted. Fixed and deployed on July 26. (Internal repository, no public link.)
- <VPBadge type='warning'>Self-hosted</VPBadge> **The Connect plugin supports ViaVersion 5.x legacy initializer unwrapping on Spigot** in [0.12.4](https://github.com/minekube/connect-java/releases/tag/0.12.4).

## July 25, 2026

- <VPBadge type='warning'>Self-hosted</VPBadge> **[Gate v0.68.29](https://github.com/minekube/gate/releases/tag/v0.68.29) updates its bundled gRPC library to a release carrying an upstream security fix.** If you self-host Gate, upgrade. This is a separate change from the PROXY-protocol security fix in v0.68.31; Gate v0.68.31 and later contain both.

## July 24, 2026

- <VPBadge type='warning'>Self-hosted</VPBadge> **The Connect plugin failed to load.** It failed to load on Paper (0.12.0), failed to start its endpoint on Spigot/Purpur (0.12.1), and failed to load at all on Velocity 4.0.0 (0.12.2). All three were regressions introduced in 0.12.0 and are fixed in [0.12.3](https://github.com/minekube/connect-java/releases/tag/0.12.3); update to [0.12.4](https://github.com/minekube/connect-java/releases/tag/0.12.4).
- <VPBadge type='warning'>Self-hosted</VPBadge> **Chat and commands were being rejected on Minecraft 1.20.5+ clients connecting through Gate**, with `Last seen update ignored previously acknowledged message at index N`. Direct connections were unaffected. Fixed in [v0.68.28](https://github.com/minekube/gate/releases/tag/v0.68.28).
