## September 14, 2026

- <VPBadge type='tip'>Connect plugin</VPBadge> <VPBadge type='warning'>Upgrade</VPBadge> **Endpoint auth failures on an organization-owned endpoint now name the real problem instead of telling you to switch organizations.** Connect 0.15.12 reports the actual condition — the connector token does not match the token stored for that endpoint name — and the fix (put the new token byte-for-byte into the connector token file, `token.json` or `CONNECT_TOKEN`, not `config.yml`, then restart), instead of blaming the Minekube organization; the endpoint/token mismatch error gained the same guidance. 0.15.13 changes only the release pipeline (it retries a Modrinth read-back), so it adds no plugin behaviour of its own; install [0.15.13](https://github.com/minekube/connect-java/releases/tag/0.15.13), which contains the 0.15.12 fix.

## September 13, 2026

- <VPBadge type='tip'>Gate</VPBadge> <VPBadge type='warning'>Upgrade</VPBadge> **Reserved names stay blocked for offline players arriving through Connect, even when the proxy runs `onlineMode: true`.** Gate v0.71.16 blocks unsafe offline usernames, v0.73.0 scopes the offline username blacklist to Connect so direct-listener setups keep their own policy, and v0.73.13 fixes the case reported from a public endpoint, where an offline identity completed login under a reserved premium name with no kick — the check now reads whether the player is authenticated, not only the proxy's online-mode setting. Install [v0.73.13](https://github.com/minekube/gate/releases/tag/v0.73.13).

- <VPBadge type='tip'>Gate</VPBadge> <VPBadge type='warning'>Upgrade</VPBadge> **Players joining through a premium Connect tunnel keep their authenticated identity, and their login no longer hangs.** [v0.73.12](https://github.com/minekube/gate/releases/tag/v0.73.12) stops Gate's accepted-connection wrappers from hiding the identity Connect had already authenticated, which made Gate treat the player as unauthenticated and send a Java EncryptionRequest into the tunnel.

## September 10, 2026

- <VPBadge type='tip'>GeyserLite</VPBadge> <VPBadge type='warning'>Upgrade</VPBadge> **GeyserLite keeps up with current Bedrock clients.** v0.5.22, v0.5.26 and v0.5.27 each carry a new upstream Geyser revision (Gate [v0.73.10](https://github.com/minekube/gate/releases/tag/v0.73.10) bundles v0.5.27); install [v0.5.27](https://github.com/minekube/geyserlite/releases/tag/v0.5.27), which contains them all with builds attached. v0.5.23 and v0.5.24 repaired the release pipeline that had published some releases without downloadable assets, and v0.5.25 shipped without builds — do not pin it.

## September 4, 2026

- <VPBadge type='tip'>Gate</VPBadge> <VPBadge type='warning'>Upgrade</VPBadge> **Gate stops running with a dead Bedrock listener.** [v0.72.6](https://github.com/minekube/gate/releases/tag/v0.72.6) surfaces unexpected managed GeyserLite exits and bridge-listener failures from the Bedrock runtime, so Gate and Moxy exit and their supervisor can restart them, instead of keeping healthy Java and HTTP health endpoints while the public Bedrock listener is gone; config reloads fail closed rather than leaving Bedrock absent.

## September 3, 2026

- <VPBadge type='tip'>Connect plugin</VPBadge> <VPBadge type='warning'>Upgrade</VPBadge> **Configs without a Bedrock-identity section get safe defaults, and an existing `config.yml` loads again on Velocity.** 0.15.10 fills the missing Bedrock-identity section with safe Minekube metadata defaults and warns the operator while leaving explicit sections — including quoted YAML keys — untouched; 0.15.11 fixes a crash 0.15.10 introduced on Velocity, where having any `config.yml` failed the load with a misleading "delete the config file" message. Install [0.15.11](https://github.com/minekube/connect-java/releases/tag/0.15.11), which contains both; do not pin 0.15.10 on Velocity.
