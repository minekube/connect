# Connect Docs Agent Notes

This package builds the public Connect documentation and blog with Astro
Starlight and uses the canary-first Cloudflare Workers Static Assets deployment procedure
in [README.md](README.md).

## Scope

- Source pages live under `src/content/docs/` (`guide/`, `blog/`, `changelog/`);
  theme overrides and components under `src/components/`, markdown extensions
  in `src/plugins/markdown.mjs`, feeds and LLM routes in `src/pages/`, static
  files in `public/`.
- Do not edit `dist/` as source. It is generated by the docs build.
- URLs are part of the contract: `build.format: 'preserve'` plus
  `src/plugins/index-pages.mjs` reproduce the old VitePress file layout, and
  heading ids use the VitePress slug algorithm so existing `#anchors` resolve.
- Changes outside `.web` may belong to the Connect codebase, not the docs site.

## RSS And Static File Links

When changing RSS or other static-file navigation:

- Prefer a real browser click test over HTML inspection alone.
- Verify local built output, the isolated Worker canary, and production when
  the task is production-facing.
- Confirm `https://connect.minekube.com/feed.rss` and
  `https://connect.minekube.com/changelog.rss` return
  `content-type: application/rss+xml`.
- Confirm visible RSS controls land on their corresponding `.rss` URL, not a
  `.rss.html` route.
- **Badges must survive into feeds.** Feed readers strip unknown markup, so a
  badge marker would silently disappear for subscribers. `src/pages/changelog.rss.ts`
  flattens `.mk-badge` spans to `<strong>` - keep that when adding markup to
  feed-rendered pages. This fails silently: the page looks right and only the
  feed is wrong.
- **A feed's channel description is its own honesty surface.** Subscribers see
  it once and never see the page's scope wording, so a scope or coverage claim
  has to be corrected in both places in the same change.

## Changelog

The public changelog is published at `/changelog/` from two files:
`src/content/docs/changelog/index.md` (the standing header, which owns the entry policy)
and a dated batch file such as `src/content/docs/changelog/2026-07-27.md` pulled in with
`<!--@include:-->`. The batch filename and its frontmatter `date` are the
**publication** date, not the coverage-end date; the covered range lives in the
title. Rename the file and the frontmatter together if a batch slips, and update
the `<!--@include:-->` line to match.

Two things in those files are load-bearing, not style:

- **Every entry is one long source line.** Entries start with `<Badge>` tags
  and the changelog script splits each list item into title, pills and body;
  keep entries unwrapped. Verify by reading built HTML, never the markdown.
- **The RSS link is a raw `<a target="_blank">`**, so it opens the feed file
  rather than navigating the docs page.
- **A release page that exists is not a build you can download.** An `Upgrade`
  badge linking a tag with zero release assets sends readers to a dead end that
  no dead-link check catches, because the tag URL itself returns 200. Check
  before linking: `gh api repos/<owner>/<repo>/releases/tags/<tag> --jq
  '[.assets[]] | length'`. If it is 0, name the closest later release that does
  have assets and contains the change (`gh api repos/.../compare/<tag>...<newer>`
  reporting `ahead` proves containment).

`src/pages/changelog.rss.ts` emits a second feed at `/changelog.rss` from
`changelog/20*.md`. The retired `/guide/changelog` route 301s from
`public/_redirects` and `worker.mjs`. `scripts/check-docs.mjs` guards the content contract,
and `scripts/check-changelog-layout.mjs` uses real Chrome geometry to guard the
Cloudflare-style entry-by-entry rail, seamless segment/node alignment, sticky
entry-date boundaries, filtering, and the rail-free mobile layout. Do not
replace that browser check with source-string or screenshot-only assertions.

## Build And Verification

Use the Node version managed by the repository tooling:

```sh
cd .web
mise exec node@24 -- corepack yarn check:docs
mise exec node@24 -- corepack yarn build
mise exec node@24 -- corepack yarn test:worker
mise exec node@24 -- corepack yarn check:changelog-layout
```

## LLM Routes

`src/pages/llms.txt.ts`, `llms-full.txt.ts` and `[...slug].md.ts` generate `/llms.txt`, `/llms-full.txt`, and per-page
`.md` files during the build. `src/plugins/llms.ts` excludes include fragments, dated changelog partials, and placeholder or
component-only pages. Do not edit generated Markdown in `dist`; `scripts/check-llms.mjs` validates the routes after every
build.

For browser verification of built docs, serve `dist` (`yarn serve` runs
`astro preview`) and test the generated site rather than source files. Do not serve it in
single-page-app fallback mode (for example `serve -s`): every clean URL then
returns the home page HTML, and the hydrated result looks like a broken page.

## Deployment Completion

Do not call a production docs fix complete from a merge alone. Check each layer:

- GitHub checks pass.
- The `connect-docs-canary.minekube.com` Worker deployment succeeds before production is
  considered.
- Deploy the production custom hostname only after current validation and
  explicit authorization.
- The relevant Worker canary behaves correctly.
- The production URL behaves correctly with a browser smoke test.

## Front End Notes

- Motion: animations always play, also with the OS reduced-motion setting on (the site owner chose this). Do not add `prefers-reduced-motion` switches.
- Security headers for production live in `public/_headers` (`/*` block). The
  Content-Security-Policy lists every outside host the site loads from:
  YouTube (player, thumbnails, storyboard frames), PostHog (`ph.minekube.com`),
  GitHub avatars and API, fly.io flag images. Adding an external script, image,
  frame or fetch target means adding its host there, or the browser blocks it.
  Search needs `'wasm-unsafe-eval'` (Pagefind runs WebAssembly).
- The hero video's ambient light uses YouTube storyboard frames. Their URLs in
  `src/components/Home.astro` (`video-board`) are signed by YouTube and can
  stop working eventually; the glow then falls back to the thumbnail. Refresh
  them from the `playerStoryboardSpecRenderer` spec of the watch page (level 1,
  80x45 frames) if that happens.
- The light/dark control is `src/components/ThemeSwitch.astro` (overrides
  Starlight's `ThemeSelect`); it writes the same `starlight-theme` key.
- `src/pages/search-index.json.ts` feeds the search fallback; keep its skip
  list in line with the pages that should not be found (include partials,
  dated changelog batches).
